# ITニュース行動提案アプリ - フロントエンド仕様書・設計書

## 1. プロジェクト要件 (What)
* **目的:** 単なるニュースリーダーではなく「今日何をすべきかが分かる」意思決定ツール。
* **絶対制約 (課金ゼロ):** バックエンド推論は無料枠やローカルで完結し、インフラは「Supabase (無料枠)」を採用。
* **UI/UX 要件（行動提案と優先順位の強化）:**
  * **テーマ:** サイバー感のあるダークモード（黒・濃紺ベースにネオングリーンのアクセント）。
  * **ユーザー別最適化:** ヘッダー等に「個人モード / 企業モード」の切替スイッチを実装（状態はローカルストレージに保存）。
  * **優先順位ファースト:** 記事一覧は新着順ではなく「最重要→重要→低」の優先順位でソートして表示する。
  * **記事カード (ArticleCard) の動的プレビュー表示【追加仕様】:**
    * 各記事カード上に、現在のモード（個人/企業）に応じた「行動提案」のプレビュー（最大2行・アイコン付き）を表示する。
    * トグルスイッチによるモード切替時、ダッシュボード上の全カードのプレビュー文言が即座に切り替わり、詳細モーダルを開かなくても視覚的な変化がひと目で分かるようにする。
  * **記事詳細モーダル:** 画面を切り替えずに以下を表示する。
    1. 要点（箇条書きで短く）
    2. 前回からの変化・差分
    3. 行動提案（モード切替状態に応じて「個人向け」か「企業向け」を出し分ける）
  * **レスポンシブ設計:** PC画面は左側サイドバー＋記事グリッド表示。スマホ画面はボトムナビ＋縦1列表示。

## 2. システム設計 (How)
* **技術スタック:** Next.js 15, TypeScript, Tailwind CSS, shadcn/ui, Supabase, Zustand (状態管理)
* **DB設計 (Supabase `articles` テーブル):**
  * `id` (UUID, PK), `title` (VARCHAR), `url` (TEXT)
  * `summary` (TEXT): 箇条書きの要点
  * `trend_diff` (TEXT): 前回からの変化・差分
  * `action_individual` (TEXT): 個人向けの行動提案
  * `action_enterprise` (TEXT): 企業向けの行動提案
  * `category` (VARCHAR): 記事カテゴリ
  * `priority_label` (VARCHAR): 最重要(High)・重要(Mid)・低(Low)のラベル
  * `importance` (INT): ソート用の数値（高=5, 低=1）
  * `published_at` (TIMESTAMP)
  * 制約: `url` カラムに対する UNIQUE 制約（二重登録防止）
